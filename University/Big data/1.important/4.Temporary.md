
# How it all works?

instead of writing map reduce methods and logic in either java or python, you instead use a specialized script language like hive or pig that will transfer those scripts into meaningful mapreduce function with their own engine/compiler

```
Pig Latin script --> Pig Engine --+
								     +--> MapReduce jobs --> HDFS
HiveQL query --> Hive compiler --+ 
```

  
| **Pig**       | **Hive**                                                                         |                                                                        |
| ------------- | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Language      | **Pig Latin** – a procedural *data-flow* language: you write a sequence of steps | **HiveQL** – a declarative, SQL-like language: you describe the result |
| Created by    | Yahoo!                                                                           | Facebook                                                               |
| Schema        | Optional (you can declare it in LOAD ... AS (...))                               | Required: you create tables first, then load data                      |
| Typical user  | Data scientists, programmers who like step-by-step scripts                       | Analysts and developers who already know SQL                           |
| Translated to | MapReduce jobs (Tez also possible)                                               | MapReduce jobs (or Tez / Spark)                                        |
| Shell         | grunt> (started with pig)                                                        | hive> (started with hive) or Beeline                                   |
| Script files  | .pig                                                                             | .hql / .sql                                                            |

# Pig

Pig is made of two modules: Pig Latin (the high-level procedural language) and the Pig Engine (parses, optimises and automatically executes the script as a series of MapReduce jobs on a Hadoop cluster)

## Pig architecture

![[image-470.png]]

When you submit a Pig Latin script it goes through the following stages:
1. Query parser – checks the syntax of the script.
2. Semantic checking – checks that aliases, fields and types make sense.
3. Logical optimizer – applies logical optimisations such as projection and push-
down.
4. Logical physical translator→ – converts the logical plan to a physical plan.
5. Physical MapReduce translator (compiler)→ – compiles the physical plan into
a series of MapReduce jobs.
6. Execution engine – launches the jobs on the Hadoop cluster; results are written
to HDFS.
