Here are short examples for each of the special path and file naming characters in the Linux shell:

## Paths
---
### `~` (Tilde)
Represents your home directory (e.g., `/home/yourusername`).

* **Example:** Navigate to your home directory.
    ```bash
    cd ~
    ```
* **Example:** Create a file named `notes.txt` directly in your home directory.
    ```bash
    touch ~/notes.txt
    ```

### `.` (Dot)
Represents the current directory you are in.

* **Example:** Run an executable script named `my_script.sh` located in your current directory. (The `./` is often needed to explicitly tell the shell to look in the current path).
    ```bash
    ./my_script.sh
    ```
* **Example:** List the contents of the current directory (same as `ls` without arguments, but explicitly stating `.`).
    ```bash
    ls .
    ```

### `..` (Double Dots)
Represents the parent directory (one level up) of your current directory.

* **Example:** Move up one directory level.
    ```bash
    cd ..
    ```
* **Example:** Copy a file named `report.pdf` from your current directory to the parent directory.
    ```bash
    cp report.pdf ..
    ```

# `/` (Root Directory)

The single forward slash `/` represents the **root directory**, which is the highest level in the Linux file system hierarchy. All other directories and files branch out from here.

* **Example:** List the immediate contents of the root directory.
    ```bash
    ls /
    ```
    This command will typically show top-level directories like `home`, `etc`, `usr`, `bin`, `var`, `tmp`, etc.

## File Naming (Wildcards / Globbing)
---
### `*` (Asterisk)
Matches zero or more characters.

* **Example:** List all files in the current directory that end with `.log`.
    ```bash
    ls *.log
    ```
* **Example:** Copy all files starting with `data_` to a directory named `archive/`.
    ```bash
    cp data_* archive/
    ```

### `?` (Question Mark)
Matches exactly one single character.

* **Example:** List files like `photo1.jpg`, `photo2.jpg`, `photoA.jpg`, but not `photo10.jpg`.
    ```bash
    ls photo?.jpg
    ```
* **Example:** Remove files named `part_a.txt`, `part_b.txt`, etc.
    ```bash
    rm part_?.txt
    ```

### `[]` (Square Brackets)
Matches any single character within the brackets, or a range of characters.

* **Example:** List files named `fileA.doc` or `fileB.doc` or `fileC.doc`.
    ```bash
    ls file[ABC].doc
    ```
* **Example:** List files named `chapter1.txt`, `chapter2.txt`, ..., `chapter9.txt`.
    ```bash
    ls chapter[0-9].txt
    ```
* **Example:** List files named `doc_x.pdf` where `x` is any lowercase letter.
    ```bash
    ls doc_[a-z].pdf
    ```

# `!` for Negation in Character Classes `[]`

When `!` is the **first character inside square brackets `[]`**, it negates the character set, meaning it matches any single character *not* in the specified set.

* **Example:** List files that have a single non-alphanumeric character in a specific position.

    Let's create some files to demonstrate:
    ```bash
    touch document-1.txt  # Has a hyphen (non-alphanumeric)
    touch document_2.txt  # Has an underscore (non-alphanumeric)
    touch documentA.txt   # Has a letter (alphanumeric)
    ```

    Now, use `ls` with the negated character class:
    ```bash
    ls document[ !A-Za-z0-9].txt
    ```

    * **Expected Output:**
        ```
        document-1.txt  document_2.txt
        ```
    * **Explanation:** The pattern `[ !A-Za-z0-9]` matches any single character that is *not* a letter or a digit. Therefore, `document-1.txt` (because of `-`) and `document_2.txt` (because of `_`) are matched, while `documentA.txt` is not.

# `ln` (Link)

The `ln` command is used to create links between files. There are two main types of links: hard links and symbolic (soft) links.

## Hard Links (`ln`)

A hard link is essentially an additional name for an existing file. When you create a hard link to a file, you're creating another directory entry that points to the *exact same inode* (the data structure that stores the actual content and metadata of a file on the disk).

* **Key Characteristics:**
    * All hard links to a file are equally important. Deleting one hard link does *not* delete the file's data until all hard links to that file are removed.
    * Hard links can only be created for files (not directories).
    * Hard links cannot span across different file systems (partitions or disks).
    * They share the same inode number as the original file.

* **Example:** Create a hard link named `my_document_link.txt` to an existing file called `my_document.txt`.
    ```bash
    touch my_document.txt # Create an original file first
    ln my_document.txt my_document_link.txt
    ls -li my_document.txt my_document_link.txt
    # Notice that both files will have the same inode number in the 'ls -i' output.
    ```

## Symbolic (Soft) Links (`ln -s`)

A symbolic link (often called a "symlink" or "soft link") is a special type of file that contains a reference to another file or directory in the form of an absolute or relative path. It's similar to a shortcut in Windows or an alias in macOS.

* **Key Characteristics:**
    * A symbolic link is a distinct file from its target. If the original file or directory is deleted, the symbolic link will become "broken" (it points to a non-existent target).
    * Symbolic links can be created for both files and directories.
    * Symbolic links can span across different file systems.
    * They have their own unique inode number.

* **Example:** Create a symbolic link named `project_data` in your home directory that points to a directory located at `/var/www/html/data`.
    ```bash
    mkdir -p /var/www/html/data # Create target directory (if it doesn't exist)
    ln -s /var/www/html/data ~/project_data
    ls -l ~/project_data
    # Output will show something like: lrwxrwxrwx ... project_data -> /var/www/html/data
    ```

# Input/Output Redirection Examples

Redirection allows you to change where a command gets its input from or where it sends its output.

## `Cmd < fichier`
---
**Description:** Redirects the **standard input** (stdin) of a command (`Cmd`) to come from a `fichier` (file), instead of the keyboard.

* **Example:** Count the number of lines in `my_text.txt` by providing it as input to `wc -l`.
    ```bash
    echo "Line 1" > my_text.txt
    echo "Line 2" >> my_text.txt
    wc -l < my_text.txt
    # Output: 2
    ```

## `Cmd > fichier`
---
**Description:** Redirects the **standard output** (stdout) of a command (`Cmd`) to `fichier`. If `fichier` exists, it will be **overwritten**. If it doesn't exist, it will be created.

* **Example:** Save the list of files in the current directory to `file_list.txt`.
    ```bash
    ls > file_list.txt
    # The content of 'file_list.txt' will now be the output of 'ls'.
    ```

## `Cmd >> fichier`
---
**Description:** Redirects the **standard output** (stdout) of a command (`Cmd`) to `fichier`. If `fichier` exists, the output will be **appended** to its current content. If it doesn't exist, it will be created.

* **Example:** Add the current date and time to the end of `log.txt`.
    ```bash
    echo "First entry" > log.txt # Create initial log file
    date >> log.txt
    # The content of 'log.txt' will now include "First entry" followed by the date.
    ```

## `Cmd 2> fichier`
---
**Description:** Redirects the **standard error** (stderr, file descriptor 2) of a command (`Cmd`) to `fichier`. If `fichier` exists, it will be **overwritten**. If it doesn't exist, it will be created. This captures error messages.

* **Example:** Try to list a non-existent file and save the error message to `errors.txt`.
    ```bash
    ls non_existent_file 2> errors.txt
    # 'errors.txt' will contain the error message from 'ls'.
    ```

## `Cmd 2>> fichier`
---
**Description:** Redirects the **standard error** (stderr, file descriptor 2) of a command (`Cmd`) to `fichier`. If `fichier` exists, the error output will be **appended** to its current content. If it doesn't exist, it will be created.

* **Example:** Append error messages from a command to an existing `full_log.txt`.
    ```bash
    ls existing_file 2>> full_log.txt # No error, so nothing appended yet
    ls non_existent_file 2>> full_log.txt # Error message appended to full_log.txt
    ```

## `Cmd << DELIMITER` (Here-documents)
---
**Description:** This redirects standard input to a command from the lines that follow, up to a specified `DELIMITER`. This is useful for providing multi-line input directly within a script or on the command line.

* **Example:** Provide multi-line text directly to the `cat` command to create a file.
```bash
    cat << EOF > my_letter.txt
    Dear User,
    This is a test letter.
    Sincerely,
    Gemini
    EOF
    # 'my_letter.txt' will contain all lines between 'EOF' and 'EOF'.
```

## `n>&m` (File Descriptor Duplication)
---
**Description:** Associates file descriptor `n` (e.g., 1 for stdout, 2 for stderr) with file descriptor `m`. This is often used to redirect standard error to the same location as standard output.

* **Example:** Redirect both standard output and standard error to the same file (`output_and_errors.txt`).
    ```bash
    ls existing_file non_existent_file > output_and_errors.txt 2>&1
    # Both the successful output (if any) and the error message will be in 'output_and_errors.txt'.
    # The '2>&1' means "send file descriptor 2 (stderr) to the same place as file descriptor 1 (stdout)".
    ```


# `|` (Pipe)

The pipe operator `|` is a fundamental concept in the Linux shell. It takes the **standard output (stdout)** of the command on its left and feeds it directly as the **standard input (stdin)** to the command on its right. This allows you to chain commands together, creating powerful workflows.

* **Example:** List all files in the current directory, and then filter that list to only show lines containing the word "report".
    ```bash
    ls -l | grep "report"
    ```
    * **Explanation:**
        1.  `ls -l` lists the contents of the current directory in a long format.
        2.  The `|` takes that entire `ls -l` output.
        3.  `grep "report"` receives that output as its input and filters it, displaying only the lines that contain the string "report".


# `expand`

The `expand` command converts **tab characters into space characters** in its input, writing the result to standard output. This is useful for ensuring consistent indentation in files, especially when files might be viewed in environments where tab widths vary.

* **Example:** Convert tabs in `my_code.py` to spaces, assuming a default tab width of 8.
    ```bash
    # First, create a dummy file with a tab
    echo -e "def func():\tpass" > my_code.py
    # Now, expand the tab
    expand my_code.py
    # Expected output: "def func():        pass" (tab replaced by 8 spaces)
    ```

# `unexpand`

The `unexpand` command performs the opposite operation of `expand`: it converts **space characters into tab characters**. This can be useful for reducing file size or for maintaining consistent indentation where tabs are preferred.

* **Example:** Convert leading spaces in `my_formatted_text.txt` back into tabs.
    ```bash
    # First, create a dummy file with leading spaces
    echo "    This line has spaces." > my_formatted_text.txt
    # Now, unexpand the spaces
    unexpand my_formatted_text.txt
    # Expected output (assuming default tab stop of 8): "\tThis line has spaces."
    ```

The `split` command is used to **divide a file into smaller pieces** (multiple output files). This is very useful when dealing with very large files that need to be transferred, processed, or stored in smaller chunks. By default, `split` creates new files named `xaa`, `xab`, `xac`, and so on.

## Combining Criteria with Logical Operators

You can combine multiple criteria using logical operators to create more complex search queries:

* **`critère1 critère2`** or **`critère1 -a critère2`**: Corresponds to the **"AND"** logical operator. Both criteria must be true.
    * **Example:** Find files named `report.txt` that are also owned by `john`.
        ```bash
        find . -name "report.txt" -a -user john
        # or more simply:
        find . -name "report.txt" -user john
        ```

* **`!critère`**: **"NOT"** logical operator. Inverts the meaning of the criterion.
    * **Example:** Find files that are *not* regular files (e.g., directories, symlinks).
        ```bash
        find . ! -type f
        ```

* **`\( critère1 -o critère2 \)`**: **"OR"** logical operator. At least one of the criteria must be true. The parentheses must be escaped (`\(` and `\)`) because they are special characters in the shell, and they group the OR condition.
    * **Example:** Find files that are either named `error.log` OR are larger than 10MB.
        ```bash
        find . \( -name "error.log" -o -size +10M \)
        ```

# `chmod` (Change Mode / Permissions)

The `chmod` command is used to **change the file system permissions** (read, write, execute) of files and directories. Permissions determine who can do what with a file or directory. There are two main ways to set permissions: **octal (numeric) mode** and **symbolic mode**.

* **Example (Basic `chmod` - Octal Mode):** Give the owner read, write, and execute permissions, and others read and execute permissions for `my_script.sh`.
    ```bash
    touch my_script.sh
    chmod 755 my_script.sh
    ls -l my_script.sh
    # Output: -rwxr-xr-x 1 user user ... my_script.sh
    ```

|-------------|-----------------------------------------------------------------------------|-----------------------------|

---

# `chmod` Symbolic Approach

The symbolic mode uses letters and symbols to specify permission changes, making it more human-readable than octal mode for specific adjustments.

The general format is `chmod WHO OPERATION PERMISSIONS FILE(s)`.

* **WHO (Who the permission applies to):**
    * `u`: user (owner)
    * `g`: group
    * `o`: others
    * `a`: all (u, g, and o) - this is the default if `WHO` is omitted.

* **OPERATION (How to change permissions):**
    * `+`: Add a permission
    * `-`: Remove a permission
    * `=`: Set the exact permissions (overwriting existing ones)

* **PERMISSIONS (Which permissions to change):**
    * `r`: read
    * `w`: write
    * `x`: execute

| Symbolic Example | Description                                                                 | Equivalent Octal |
|------------------|-----------------------------------------------------------------------------|------------------|
| `u+x file.sh`    | Add execute permission for the owner.                                       | `chmod u+x file.sh` |
| `g-w file.txt`   | Remove write permission for the group.                                      | `chmod g-w file.txt` |
| `o=r file.txt`   | Set others' permission to read only (remove any other permissions for others). | `chmod o=r file.txt` |
| `a+rw file.txt`  | Add read and write permissions for all (user, group, others).               | `chmod a+rw file.txt` |


* **Example (Symbolic `chmod`):**
    1.  Make `my_script.sh` executable for the owner.
        ```bash
        touch my_script.sh
        chmod u+x my_script.sh
        ls -l my_script.sh
        # Output: -rwx------ 1 user user ... my_script.sh
        ```
    2.  Remove write permission for "others" on `my_document.txt`.
        ```bash
        touch my_document.txt
        chmod o-w my_document.txt
        ls -l my_document.txt
        # Output: -rw-r--r-- 1 user user ... my_document.txt (if it was rw-rw-rw-)
        ```

# `umask` (User Mask)

The `umask` command is used to **set or display the file mode creation mask**. This mask is a set of permissions that are *subtracted* from the default permissions whenever a new file or directory is created. It acts as a filter to restrict default permissions for new items.

* **Default permissions:**
    * For **files**: `666` (rw-rw-rw-)
    * For **directories**: `777` (rwxrwxrwx)

    The `umask` value is subtracted from these defaults. For example, if `umask` is `022`:
    * New file permissions: `666 - 022 = 644` (rw-r--r--)
    * New directory permissions: `777 - 022 = 755` (rwxr-xr-x)

* **Example (Viewing and Setting `umask`):**

    1.  **View the current umask value:**
        ```bash
        umask
        # Typical output might be: 0022 (octal) or 022 (often displayed without leading zero if not showing all digits)
        ```
    2.  **Temporarily set a new umask and see its effect:**
        Let's set umask to `007` (this means group and others get no permissions, owner gets defaults).
        ```bash
        umask 007
        # Now create a file and a directory
        touch new_file.txt
        mkdir new_dir
        ls -l new_file.txt new_dir
        # Expected output (assuming default 666 for files, 777 for dirs - 007 mask):
        # -rw-rw---- 1 user group ... new_file.txt (660)
        # drwxrwx--- 2 user group ... new_dir (770)
        ```
        (Note: `umask` changes are usually session-specific. To make them permanent, you'd put the `umask` command in your shell's startup file, like `.bashrc`.)

**Note:** The `umask` command itself doesn't have common options that are typically listed in a table; its primary use is to display or set the mask value directly.

# `su` (Substitute User / Switch User)

La commande `su` est utilisée pour **passer à un autre utilisateur** (ou au superutilisateur `root` si aucun nom d'utilisateur n'est spécifié) dans la même session de terminal. Cela vous permet d'exécuter des commandes avec les privilèges d'un autre utilisateur sans avoir à vous déconnecter et à vous reconnecter.

* **Exemple (Basic `su`):** Passer à l'utilisateur `otheruser`.
    ```bash
    # Supposons que vous êtes 'your_username'
    su otheruser
    # Le système vous demandera le mot de passe de 'otheruser'.
    # Une fois connecté, vous serez 'otheruser' mais votre répertoire de travail et votre environnement (PATH, etc.) resteront ceux de 'your_username'.
    ```

---

# `su -` (Simuler une connexion complète)

L'utilisation de `su -` (avec un tiret) est une variante très importante de la commande `su`. Le tiret indique à `su` de simuler une **connexion complète** du nouvel utilisateur. Cela signifie que :

* Le répertoire de travail sera changé pour le répertoire personnel du nouvel utilisateur.
* L'environnement (variables d'environnement comme `PATH`, `HOME`, etc.) sera entièrement mis à jour comme si le nouvel utilisateur s'était connecté directement.

Ceci est particulièrement important lorsque vous passez à `root`, car un environnement `root` propre est souvent nécessaire pour les tâches administratives.

* **Exemple (Utilisation de `su -`):** Passer au superutilisateur (`root`) avec son propre environnement.
    ```bash
    # Supposons que vous êtes 'your_username'
    pwd
    # Output: /home/your_username

    su -
    # Le système vous demandera le mot de passe de 'root'.
    # Une fois connecté, votre invite changera souvent pour indiquer que vous êtes root.
    pwd
    # Output: /root (ou le répertoire personnel de root)

    exit # Pour revenir à votre utilisateur précédent
    ```

The command `groupadd -R NomUtilisateur NomGroupe` is not a valid way to remove a user from a group. The `groupadd` command is only for *creating* groups.

To **remove an existing user from a group**, you typically use the `gpasswd -d` command (or `deluser user groupname` on some systems like Debian/Ubuntu).


# `chown` (Change Owner)

The `chown` command is used to **change the user owner and/or group owner of files or directories**. You must be the root user (or use `sudo`) to change the owner of a file you don't own, or to change the owner to someone else.

* **Example (Basic `chown`):** Change the owner of `document.txt` to `john`.
    ```bash
    # Create a dummy file
    touch document.txt
    sudo chown john document.txt
    # Verify the change
    ls -l document.txt
    # Expected output: -rw-r--r-- 1 john user ... document.txt
    ```
* **Example (`chown -R` - Recursive):** Change the owner of `project_folder` and all its contents to `alice`.
    ```bash
    mkdir -p project_folder/docs
    touch project_folder/file1.txt project_folder/docs/report.txt
    sudo chown -R alice project_folder/
    # All files and subdirectories inside project_folder will now be owned by 'alice'.
    ls -lR project_folder/
    ```
* **Example (`chown -h` - Affecting Symlinks):** Change the owner of a symbolic link itself, not the file it points to.
    ```bash
    # Create a target file and a symlink to it
    touch original_file.txt
    ln -s original_file.txt link_to_file.txt
    sudo chown bob original_file.txt # Owner of original file
    ls -l original_file.txt link_to_file.txt
    # original_file.txt is owned by 'bob', link_to_file.txt is owned by the current user.

    sudo chown -h carl link_to_file.txt # Change owner of the link itself
    ls -l original_file.txt link_to_file.txt
    # original_file.txt is still owned by 'bob', but link_to_file.txt is now owned by 'carl'.
    ```

# `chgrp` (Change Group)

The `chgrp` command is used to **change the group owner of files or directories**. You must either be the owner of the file (and a member of the target group) or the root user (or use `sudo`) to change a file's group.

* **Example (Basic `chgrp`):** Change the group of `document.txt` to `developers`.
    ```bash
    # Using the 'document.txt' from above (owned by 'john')
    sudo chgrp developers document.txt
    # Verify the change
    ls -l document.txt
    # Expected output: -rw-r--r-- 1 john developers ... document.txt
    ```
* **Example (`chgrp -R` - Recursive):** Change the group of `project_folder` and all its contents to `webteam`.
    ```bash
    # Using the 'project_folder' from above (owned by 'alice')
    sudo chgrp -R webteam project_folder/
    # All files and subdirectories inside project_folder will now have group 'webteam'.
    ls -lR project_folder/
    ```
* **Example (`chgrp -h` - Affecting Symlinks):** Change the group of a symbolic link itself, not the file it points to.
    ```bash
    # Using 'original_file.txt' (owned by 'bob') and 'link_to_file.txt' (owned by 'carl')
    # Let's say original_file.txt's group is 'users' and link_to_file.txt's group is 'carlgroup'
    sudo chgrp admin_group original_file.txt # Change group of original file
    ls -l original_file.txt link_to_file.txt
    # original_file.txt's group is 'admin_group', link_to_file.txt's group is 'carlgroup'.

    sudo chgrp -h test_group link_to_file.txt # Change group of the link itself
    ls -l original_file.txt link_to_file.txt
    # original_file.txt's group is still 'admin_group', but link_to_file.txt's group is now 'test_group'.
    ```
