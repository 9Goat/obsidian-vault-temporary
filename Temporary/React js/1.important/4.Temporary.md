# JSX

the first notable thing that i learned about react is the jsx syntax, a way to create a component in react is to write a function like this

```javascript
function MainContent() {  
return (
<h1>React is great!</h1>
)
}  
  
root.render(  
<div>  
<MyAwesomeNavbar />  
<MainContent />  
</div>  
)

// Note: components are not required to be self closed when calling the, sometimes we can put other elements inside of it
root.render(
<Page>Placing some elements inside</Page>
)
```

- the main function is the component where it returns jfx syntax elements, if there are multiple elements we write the return as `return (//multiple elements here)`
- and to render it we use the render element
- **Note**: render function only accepts a single root element inside it, meaning if we want to include multiple elements inside of render we have to surround them inside a single root element like div in this example
- the parameters are mainly for  decoration they are not required

## How to get the render element

first we mark an element inside our `index.html` file with an id that we are going to call later in js

```html
<body>  
<div id="root"></div>  
<script src="/index.jsx" type="module"></script>  
</body>
```

and in js we have to import a function from react and attach to it that element using getElementById

```js
import { createRoot } from "react-dom/client"

const root = createRoot(document.getElementById("root"))
```

## Fragment

instead of surrounding the code inside of a div element, *since we have to put  in a single root element*, we instead can use the built it `Fragment` component from react, the benefits of this is that we dont end up with a nested div, which may causes some problems especially with css styling if we have a global css styling for div elements

```jsx
import { createRoot } from "react-dom/client"  
import { Fragment } from "react"  
  
const root = createRoot(document.getElementById("root"))  
  
function Page() {  
return (  
<Fragment>  
<header>  
<img src="react-logo.png" width="40px" alt="React logo" />  
</header>  
<main>  
<h1>Reason I am excited to learn React</h1>  
<ol>  
<li>React is a popular library, so I will be able to fit in with all the coolest devs out there! 😎</li>  
<li>I am more likely to get a job as a front end developer if I know React</li>  
</ol>  
</main>  
<footer>  
<small>© 2024 Ziroll development. All rights reserved.</small>  
</footer>  
</Fragment>  
)  
}  
  
root.render(  
<Page />  
)
```

## using javascript inside of jsx

outside the html elements we can use simple javascript expressions, we are already familiar with that, but the challenge becomes clear when we want to write javascript expressions inside of the html elements, for example like the text inside a h1 element, to make any javascript express valid inside of html we simple have to surround them with a single curly bracket

```jsx
function App() {  
const firstName = "Joe"  
const lastName = "Schmoe"  
  
return (  
<h1>Hello {firstName} {lastName}</h1>  
)  
}
```

- this will write: `Hello Joe Schmoe`

### Destructing props

to destruct a prop we need to first learn how to destruct  a javascript object, to do that we need to declare the variable in curly brackets `{variable1,variable2}` and assign the object to them, when naming the variables inside the curly brackets we have 2 options:

1. naming them as the same name of the attributes inside the object
2. use this simple trick `{variable1:alias1,variable2:alias2}` in this case the name of the variable must match the name of the attributes inside the object, but we can use the alias as the variable holding the value of the attribute

**Example**

```js
const person = {  
img: "./images/mr-whiskerson.png",  
name: "Mr. Whiskerson",  
phone: "(800) 555-1234",  
email: "mr.whiskaz@catnap.meow"  
}

const {img, name} = person
console.log(img + name)

//OR

const {img: image, name:fullName} = person
console.log(image+fullName)
```


we can use that principal to destruct the props object and get it as separate variables, and use those variables inside our html elements without having to mention the props name

**Example**

```jsx
export default function Contact({img, name, phone, email}) {  
return (

src={img}  
alt="Photo of Mr. Whiskerson"

<img  
src="./images/mail-icon.png"  
alt="mail icon"

```

# States

when we change the value of a variable in react and try to display it, it shows the old value, why?
that is because to show the new value we need to rerender the entire component, which is why we have states in react, they provide us with a value that we can update, and a function that reneders the page when we call it

## 2 components of states

```jsx
import { useState } from 'react'; //first  we import the method responsible for states

const [index, setIndex] = useState(0)
```

- index is the variable that holds the value of the state
- setIndex is the function that accepts a single parameter to update the index value and rerender the component

this syntax is called array  destructering, this **`useState(value)`** function returns an array that composes of 2 values:

- state value
- state set value function that rerenders the component

instead of writing it with 3 lines like this

```jsx
import { useState } from 'react'; //first  we import the method responsible for states

const indexState = useState(0)

const index = indexState[0] //this is the value of the state
const setIndex = indexState[1]//this is the set function
```

## Example

```jsx
import React from "react"  
  
export default function App() {  
const [count, setCount] = React.useState(0)  
  
function add() {  
setCount(count + 1)  
}  
  
function subtract() {  
setCount(count - 1)  
}  
  
return (  
<main className="container">  
<h1>How many times will Bob say "state" in this section?</h1>  
<div className="counter">  
<button className="minus" onClick={subtract} aria-label="Decrease count">–</button>  
<h2 className="count">{count}</h2>  
<button className="plus" onClick={add} aria-label="Increase count">+</button>  
</div>  
</main>  
)  
}
```

##  Consective use state calls

what happens when we call the set state function multiple times  in a row in a single  render? take this code for example

```jsx
<button onClick={() => {  
setNumber(number + 1);
setNumber(number + 1);
setNumber(number + 1);}}
>+3</button>
```

will it make the button +3 the value it was before? **`No`** instead it will only increment it once, because the set function is still working with the old value to it is setting a static value for every call

```jsx
<button onClick={() => {  
setNumber(0 + 1);  
setNumber(0 + 1);  
setNumber(0 + 1);}
}>+3</button>
```

as you can see here, the previous value is hardcoded for the function calls, because before the renender the set function takes a snapshot of the state value and dosent update it until the rerender is finished, to fix this we can use the call back function feature of the set function

### Example

lets look at our add button example and see how to implement the call back function instead of the value parameter of the set function

```jsx
function add() {  
setCount(function(prevCount) {  
return prevCount + 1  
})  
}
```

**This is also useful for  extending the functionality of the set state, but if we just want to use it to update the value of the state we can use a simpler implementation**

```jsx
function add() {  
setCount(prevCount=> prevCount + 1)  
}
```

How will this  fix the problem?

```jsx
<button onClick={() => {  
setNumber(prevCount + 1);  //here it starts at 0
setNumber(prevCount + 1);  //here it  is 1
setNumber(prevCount + 1);} // here it is 2
}>+3</button>
```

before each function call it takes into consideration the value before meaning the final value will be 3

## Working with complex datatypes

this applies to objects and array when we want to modify the value of an object or array we cant just write a static value, instead of have to do the following

- use the set function with the callback function parameter
- create a temporary variable that holds the current items of  the state using this syntax **`...objectName/arrayName`** at the start of the object, then we add the item we want to add/modify
- return that temporary variable

### Example with array

```jsx
import React from "react"  
  
export default function App() {  
const [myFavoriteThings, setMyFavoriteThings] = React.useState([])  
  
function addFavoriteThing() {  
setMyFavoriteThings(  
prevFavThings => [  
...prevFavThings,  //previous items of the  array
<p>Test</p>  //the item we want to add at the end of  they array
]  
)  
}  
  
return (  
<main>  
<button onClick={addFavoriteThing}>Add item</button>  
<section aria-live="polite">  
{myFavoriteThings}  
</section>  
</main>  
)  
}
```


### Example with objects

```jsx
export default function App() {  
const [contact, setContact] = React.useState({  
firstName: "John",  
lastName: "Doe",  
phone: "+1 (212) 555-1212",  
email: "itsmyrealname@example.com",  
isFavorite: false  
})  
  
function toggleFavorite() {  
setContact(prevContact => ({  
...prevContact,  
isFavorite: !prevContact.isFavorite  
}))  
}
```

How does this work? wont this result in a duplicate attribute since the object already contains the **isFavorite** attribute?

**Correct** this will create a duplicate attribute, but in js it is possible to have duplicate attributes in objects, because js will only consider the **LAST** duplicate attributes and ignore the ones before it, which is why is it **NECESSARY** the place our modification at the **END** of the object modification before deconstructing the object

**How it looks like**

```jsx
function toggleFavorite() {  
setContact(prevContact => ({  
firstName: "John",  
lastName: "Doe",  
phone: "+1 (212) 555-1212",  
email: "itsmyrealname@example.com",  
isFavorite: false, //will get ignored by js because it is NOT the last duplicate
isFavorite: !prevContact.isFavorite //  the modified attribute that js will use
}))  
}
```
